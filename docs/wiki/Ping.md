ICMP (IPv4/IPv6) or TCP-connect ping, continuous or N count, live latency graph, loss/min/avg/max.

Like every tab: the run bar (the main field first, **▶ Start** right after it), the other settings folded under **Options** with their values shown as chips, a status row under it with what the run found on the left and **Copy** / **Save…** on the right, and a short explanation of what to do before the first run. Enter in the main field starts a run; Esc stops it.

**ICMP** works as a normal user on both systems: Windows uses the IP Helper API (`IcmpSendEcho2` / `Icmp6SendEcho2`), Linux uses unprivileged ping sockets (`SOCK_DGRAM` / `IPPROTO_ICMP`), which need your group inside `net.ipv4.ping_group_range` (the default on Fedora, Ubuntu, Arch and most systemd distros; otherwise it falls back to the system `ping`). **TCP** times a connection to a port instead, for hosts that drop ICMP.

**Wake.** A MAC in the box (`00:11:32:ab:cd:ef`) turns **▶ Start** into **▶ Wake**: a Wake-on-LAN magic packet (UDP port 9, the same one a Map card's **Wake** sends). With an address known, typed after the MAC (`00:11:32:ab:cd:ef 192.168.1.50`) or where the sweep or Map last saw it, it's **▶ Wake & wait**: a ping every 5 s for up to 3 minutes, ending with *up after N s* or *No answer*. No new field: a line in the ICMP/TCP switch's place says what it will do. A name the last sweep or the Map saw with a MAC stays a normal ping on **▶ Start** and Enter, with a separate **Wake** button beside it that wakes it and waits the same way. Off this computer's network the packet also goes to the address itself and, when the address is inside a range the last sweep covered whole (a /22 to /30 such as `10.20.0.0/24`, whether or not the device answered), that range's broadcast (`10.20.0.255`) as a directed broadcast. That only helps if the range is the device's real subnet and its router forwards directed broadcasts (off by default on most). Full scan never wakes anything. Wi-Fi adapters rarely wake, and Windows Fast Startup often stops a PC waking from shutdown: see the manual's Troubleshooting.

**CSV columns** (Results → Export → CSV): target, mode, port, seq, from, status, rtt_ms, ttl, bytes. See [[Results]].
