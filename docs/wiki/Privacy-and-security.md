Built for sites with regulated data (HIPAA): zero trust and as little as possible.

- **Two requests on start, both optional.** When the app opens it looks up the public IP (one DNS query to OpenDNS) and asks GitHub for the latest release (one HTTPS request to `api.github.com`, carrying only the app's version in its user agent). Both can be turned off in **Settings → Network**; with both off, launching the app sends nothing. An update is only linked, never downloaded or installed.
- **Everything else only when you run it**: the public-IP lookup on **Refresh**, a full scan or a **Domain Health** run (which also asks the blacklists about this network's public address, so their operators see it, as they do the domain's mail servers), a full scan's network checks (one plain-HTTP GET of `cp.cloudflare.com/generate_204` to spot a captive portal, a TLS handshake with www.cloudflare.com, github.com and www.microsoft.com to read their certificates, the time from time.cloudflare.com, time.windows.com or pool.ntp.org, else an HTTPS site's Date header, and up to about 30 pings with *Don't Fragment* to 1.1.1.1 for the path MTU; Host info's DHCP server, lease and DNS servers, the Wi-Fi snapshot and the list of nearby access points are read from this computer's own settings, nothing sent), **Scan Wi-Fi** in a Network checks run (the Wi-Fi adapter sends probe requests on each channel, as any device looking for networks does), a sweep's one GET of each device's own web page where a web port answered, the DNS and domain-health queries you start, MTA-STS/RDAP over HTTPS only (redirects too; an RDAP service with no HTTPS address isn't asked) with the OS trust store, the Speed Test's transfers to Cloudflare, **Check now**, and **Help**, which opens the wiki in your browser. Links open with the system's own launcher (`xdg-open`, `explorer.exe`, `open`, by absolute path), web links only; from the AppImage, its bundled libraries are kept out of the browser's environment. No telemetry, no accounts.
- **SNMP only when asked, to one device.** The inspector's **SNMP** button (Subnet Sweep and Map cards) sends SNMP v2c, then v1, to UDP 161 on the one device picked, and nothing else; a sweep or a Full scan never sends SNMP, and it's never sent across a subnet. Replies count only from that address and port 161, matched to the request ID, and the decoder is tested against damaged and random packets. The community is kept in memory for the session only: never in settings, Results, the Site report or a Site Bundle. The device's `sysContact` (often a person's name, email or phone) shows in the inspector only and is left out of Results, the Site report and the Site Bundle. Readings belong to the open site: opening another one clears them, and a read under way holds the switch, so nothing read at one site is shown or logged at another (unless you carry what's open into a new site, when they go along with its Results).
- **Sanitized on this machine before anything is saved or shared**: UniFi exports (secret fields stripped, and any value holding key material whatever it's called; client notes, email and phone always dropped; client names only when you choose *full*), SonicWall exports (an allowlist of fields; comments redacted), Meraki exports (secrets never copied; comments, rule names and DHCP reservation names redacted), tech notes and Known problems (what you mark, plus the loaded configs' secrets). In the Claude Handoff, **Client names** also covers phones', laptops' and PCs' names in the sweep inventory and Meraki DHCP reservations.
- **Clipboard.** On Windows, everything the app copies (its Copy buttons, and Ctrl+C, Ctrl+X or the right-click menu in any text box, Notes included) is marked to stay out of clipboard history (Win+V), cloud clipboard sync and clipboard managers. When that can't be done (another program, such as a remote-desktop session, is holding the clipboard), nothing is copied and a message says so: the app never makes an unmarked copy. On Linux the app's copies are marked for clipboard managers (Klipper and others) to leave out of their history. When the app closes, it clears the clipboard if it still holds the app's last copy (something you copied elsewhere since is left alone).
- **At rest**, everything is in one data folder (`%APPDATA%\is-alive` on Windows, `~/.config/is-alive` on Linux, or `is-alive-data` beside the program): the settings file (theme, choices, the open site's name, the backdrop picture path), `startup.log` (which renderer opened the window), and for Scratch and each site (`sites/<site>`) its `notes.md` (redacted), `notes-allow.json` (values you chose to keep), `map-notes.json` (card notes, redacted), `maps/` (saved maps: the devices drawn, with their names, addresses and MACs), `map-clients.txt`, `results.json` (Results, when **Keep with site** is on; Scratch's for 24 hours) and a site's `site.json` (its name and the *paths* of its configs; configs are never copied). Carrying Scratch into a new site (**New site › What's open now**) moves its notes, card notes and Results: Scratch's copies are removed once the new site has its own.
- **Input files are untrusted.** Only regular files up to 2 GB are read; decompression is capped at 2 GB per layer and document nesting at 64 levels, and what's parsed is capped lower (a Meraki export at 32 MB of JSON per file, a `/mapnetwork` map at 16 MB, a UniFi backup's kept collections at 256 MB and one record at 16 MB), so a crafted backup is refused rather than exhausting memory or the stack. The parsers are tested against truncated, bit-flipped and random input.
- **Imported scans leave people out.** An Advanced IP Scanner export brought in with Sweep's **Import scan…** never has its `user` (logged-on users) read, and its shares and printers are counted, never named, so none of them reach the report, the Map or a Site Bundle; a PC's NetBIOS name follows the Handoff's **Client names** like its name. The file is capped at 64 MB and 65,536 rows, and an XML DTD is refused. See [[Subnet Sweep|Subnet-Sweep]].
- **Input is bounded.** Text fields take at most 255 characters (2,048 for a link, 1 MB of text in Notes, 20,000 in Known problems), so a pasted log can't swell a field.
- **Nothing it writes can run.** Every save keeps the type it offers: a name typed as `notes.bat` or `report.xlsm` saves as `notes.bat.txt`, so no export becomes a script or a macro-enabled Office file. CSV cells that start with `=`, `+`, `-`, `@`, `|`, a tab or their full-width forms get a leading `'`, so Excel shows a hostile hostname or TXT record as text instead of running it as a formula. **Open…** in Notes only displays a file; Markdown links are shown, never followed.
- **Nothing has to stay behind.** With a folder named `is-alive-data` beside the program, everything is kept there and nothing in the computer's profile; and **Settings › Remove everything is-alive saved…** deletes all of it from a computer you're done with. See [[Settings and themes|Settings-and-themes]].
- **Private on disk.** On Linux and macOS the data folder is readable by your user only (mode 700, set at every start) and its files are written mode 600, so other accounts on the computer can't list the sites or read inside. On Windows the profile folder already is; a portable `is-alive-data` folder keeps the permissions of wherever it was put, so keep it in your own folder or on your own drive, not in a shared place such as `C:\` or a FAT/exFAT stick that others use.
- **Configs on a network share aren't opened by themselves.** A site remembers where its configs are; one on a share (`\\server\share\…`) isn't read when the site opens or the app starts, because looking for that server on another client's network would offer this computer's sign-in to whatever answers. Open it from Config Export when you're on that network.
- **System tools** (`ip` and `arp` for the neighbor table, `ping` as a fallback) run only from `/usr/sbin`, `/sbin`, `/usr/bin` or `/bin` with a C locale, never from a PATH lookup. On Windows the app uses the OS APIs instead.
